## 확정된 제약

### 댓글은 평문 저장

`content: string` 한 필드다. 리치 에디터를 쓰지 않는다.
백엔드 `Comment.content`가 평문 한 필드이고 FR-5.4가 "순수 텍스트 댓글 구조만 유지"로 못 박았다.

- 코드블록과 목록은 렌더 시 `react-markdown`으로 표시만 한다. 저장 형식은 안 바뀐다.
- 이미지와 동영상 첨부는 스코프 밖.
- 입력은 `textarea`다. Tiptap 같은 에디터를 붙이지 않는다.

### 멘션 저장 형식 — `@userId|` / `#endpointId|`

**이름을 본문에 박지 않는다.** id만 저장하고 렌더 시점에 해석한다.
멤버가 이름을 바꾸면 옛 댓글의 멘션도 새 이름을 따라간다.

```
@12| 확인 부탁드려요. #5| 쪽 문제로 보입니다.
```

**`|`로 끝을 막는 이유**: `@2` 뒤에 숫자가 이어지면 `@23`인지 `@2` 다음 `3`인지 갈리지 않는다.

**이 형식은 순수한 프론트 규약이다.** 백엔드는 `content`를 파싱하지 않는다.
멘션 대상은 `CreateCommentDto`의 `mentionedUserIds` / `mentionedEndpointIds`로 따로 가고,
서버는 이 문자열을 그대로 저장할 뿐이다.

### 표시 형식 — 3단 변환

`lib/`이 아니라 `comments/mentions.ts`가 갖는다. 소비처가 댓글뿐이다.

| 변환                 | 함수                 | 언제                               |
| -------------------- | -------------------- | ---------------------------------- |
| 저장 → markdown 링크 | `mentionsToMarkdown` | 본문 렌더 직전                     |
| 표시 → 저장          | `toStorage`          | 제출할 때                          |
| 저장 → 표시          | `toDisplay`          | 수정하려고 기존 댓글을 열 때       |
| 저장 → ID 배열       | `extractIds`         | DTO의 `mentionedUserIds`를 만들 때 |

**textarea에는 사람이 읽는 이름이 보인다.** 사용자는 `@희경`을 보고 치고,
제출할 때 `@12|`로 바뀐다.

**`mentionsToMarkdown`은 `react-markdown` 파싱 전에 돌아야 한다.**
파싱 후에는 이미 React 엘리먼트라 문자열 치환이 안 된다.

```
@12|  →  [@희경](mention:12)
#5|   →  [#GET /courses/:id](endpoint:5)
```

- 이름과 경로는 댓글이 들고 온 `memberMentions` / `endpointMentions`에서 꺼낸다.
  멤버 목록을 따로 조회할 필요가 없다.
- **검증 배열에 없는 id면 원문 토큰을 그대로 둔다.** 사용자가 손으로 쳐 넣은
  가짜 멘션이 칩으로 살아나지 않는다.
- 링크 텍스트의 `[`, `]`, `\`는 이스케이프한다. 한글 이름에는 없지만 path에는 들어갈 수 있다.
- 엔드포인트 표시는 대문자(`#GET /courses`), 저장은 소문자(OAS 규약).
  `#`을 남기는 것은 입력할 때 친 문자와 같게 보이려는 것이고 `@` 멘션과 대칭이다.

**`toStorage`는 긴 이름부터 바꾼다.** "희경"과 "희경민"이 있을 때 짧은 쪽을 먼저 치환하면
`@희경민`이 `@2|민`이 된다. 엔드포인트도 같다.

### 감수한 한계 3종

되돌리기 어려운 설계 선택이라 근거와 함께 남긴다.

**1. 코드블록 안의 토큰도 치환된다.** `mentionsToMarkdown`이 문자열 전체를 훑는다.
AST 단계(remark 플러그인)에서 하면 피할 수 있지만 마주칠 확률이 낮아 감수한다.

**2. 동명이인은 먼저 찾은 쪽으로 붙는다.** `toStorage`가 이름으로 되짚기 때문이다.
팝오버가 고른 id를 따로 들고 있으면 해결되지만, textarea의 캐럿 위치와 id를
동기화하는 구조가 붙는다.

**3. 팝오버로 고르지 않고 손으로 `@이름`을 쳐도 멘션으로 파싱된다.**
2번과 같은 원인이다. 오작동이라기보다 관대한 동작이라 그대로 둔다.

### 2뎁스 고정

`CommentTree = CommentView & { replies: CommentView[] }`. 대댓글에는 `replies`가 없다.

백엔드가 `normalizeReply`로 강제한다 — 대댓글에 대댓글을 달면 최상위 댓글의 자식으로 붙는다.
프론트는 이 불변을 믿고 재귀 렌더를 하지 않는다. `CommentThread`가 두 층을 평면으로 그리고,
`CommentItem`이 `isRoot` 하나로 갈린다.

## 데이터 흐름

| 동작        | 호출                                               | 응답            |
| ----------- | -------------------------------------------------- | --------------- |
| 목록        | `GET /api/endpoints/:id/comments`                  | `CommentTree[]` |
| 최상위 작성 | `POST /api/endpoints/:id/comments`                 | `Comment` 원형  |
| 대댓글 작성 | `POST /api/comments/:id/replies`                   | `Comment` 원형  |
| 수정        | `PATCH /api/comments/:id`                          | `Comment` 원형  |
| 삭제        | `DELETE /api/comments/:id`                         | `Comment` 원형  |
| 리액션 토글 | `POST /api/comments/:id/reactions`                 | —               |
| AI 요약     | `POST /api/endpoints/:id/ai-summary`               | 생성된 댓글     |
| 일괄 이동   | `PATCH /api/endpoints/:id/comments/move` `[Owner]` | —               |

**쓰기 응답은 전부 `Comment` 원형이라 화면이 쓸 수 없다.** `author`, `reactions`,
`memberMentions`가 없다. 로컬 패치가 불가능하고 목록 재조회가 유일한 방법이다
(`08-state-and-data`의 mutation 절).

**삭제된 댓글도 자리를 지킨다(FR-5.3).** 서버가 `content`를 마스킹해서 보내고
`isDeleted: true`가 붙는다. 목록에서 빼지 않는다 — 빼면 답글이 고아가 되고
누가 뭘 지웠는지의 맥락이 사라진다. 개수 집계에도 포함한다.

## 화면 구조

```
CommentPanel                    # Provider + 본문
└── CommentPanelInner
    ├── PanelHeader             # sticky top — 제목, 개수, AI 요약, 이동
    ├── 목록 (flex-1)           # CommentThread[]
    └── CommentEditor           # sticky bottom
```

**스크롤 주체는 이 패널이 아니라 컬럼(`SpecColumns`)이다.** 고정 영역을 `sticky`로 만든다.
패널이 자기 안에서 따로 스크롤하면 좁은 폭 오버레이에서 스크롤 컨테이너가 이중으로 겹친다.

**`CommentProvider`와 본문을 나눈다.** 헤더가 `isOwner`를 컨텍스트에서 읽어야 하는데
Provider와 같은 컴포넌트에 있으면 자기가 만든 값을 못 읽는다.

**`key={endpointId}`로 리마운트한다.** 엔드포인트를 바꾸면 편집 상태와 스크롤이
초기화돼야 한다. `useEffect` 동기화보다 안전하다(`06-spec-detail-plan`의 같은 판단).

### `CommentContext`가 갖는 것

바깥이 주는 값(`me`, `isOwner`, `members`, `endpoints`)에 편집 상태 둘을 더한다.

- `editing` — **한 번에 하나만 열린다.** 답글 에디터가 열린 채로 다른 곳의 수정을 누르면
  앞의 것이 닫힌다. `{ mode: "reply" | "edit", id }` 유니온이라 둘이 동시에 참일 수 없다.
- `justAddedId` — 방금 추가한 항목으로 스크롤하고 하이라이트한다.
  `scrollIntoView`는 가장 가까운 스크롤 조상을 브라우저가 찾으므로 스크롤 주체가 어디든 된다.
  하이라이트는 CSS 애니메이션이 스스로 끝내고 `onAnimationEnd`에서 상태를 비운다.

`members`는 `PublicUser[]`다. `MemberView`가 아니다 — 컨텍스트가 `role`을 쓰지 않고
Owner 판정은 `isOwner`로 이미 내려온다.

`endpoints`는 **삭제되지 않은 것만** 걸러서 받는다(FR-8.3). 에디터와 이동 팝오버가
다시 판단하지 않는다.

## 규칙

### 정렬

**오름차순(오래된 것이 위).** 댓글과 답글 모두 시간순이라 논의 흐름이 위에서 아래로 읽힌다
(Slack, GitHub 관례). 새 항목은 맨 아래에 붙고, 제출 후 `justAddedId`가
거기로 스크롤시켜 "안 보이는 곳에 등록됨" 문제를 없앤다.

### 액션 노출 조건

| 액션      | 조건                          |
| --------- | ----------------------------- |
| 답글      | 최상위 && 사람 작성 && 미삭제 |
| 수정/삭제 | 내 글 && 미삭제               |
| 리액션    | 항상 (삭제된 댓글에도)        |

- 답글이 최상위에만 있는 것은 2뎁스 고정 때문이고, AI 요약을 뺀 것은 FR-13.5다.
- AI는 로그인을 못 해 `author.id`가 내 id와 절대 안 맞는다. 수정/삭제 조건에
  `!isAiGenerated`를 따로 넣지 않아도 된다.
- `(편집됨)` 표시는 `updatedAt !== createdAt`이고 미삭제일 때만.

### 리액션

- 타입 4종은 프론트가 정의한다. 값(`REACTION_TYPE`)은 백엔드와 공유하지만
  이모지와 라벨은 `reactions.ts`가 갖는다. `Record<REACTION_TYPE, _>`라
  하나라도 빠뜨리면 컴파일 에러다.
- **표시 순서는 `REACTION_TYPES` 배열 순서를 그대로 따른다.** 따로 정하면
  값이 늘거나 순서가 바뀔 때 두 곳을 봐야 한다.
- **이모지를 쓴다.** GitHub, Slack의 관습이고 단색 아이콘보다 뜻이 즉각 읽힌다.
  "색을 아낀다"(`04-design-tokens`)의 명시적 예외이며, 리액션은 색 자체가 정보를 나른다.
- **4종을 항상 다 그리지 않는다.** 달린 것만 칩으로 보이고 추가는 팝오버에서 한다.
  패널 최소폭이 240px이라 여백을 빼면 176px밖에 안 남는다.
- **팝오버 하나가 두 일을 맡는다** — 위에서 추가와 해제, 아래에서 누가 남겼는지.
  이름을 툴팁으로 빼지 않은 이유는 툴팁이 터치 기기에서 안 열리기 때문이다.
  좁은 폭에서도 오버레이로 동작하므로 툴팁에만 있는 정보는 모바일에서 통째로 사라진다.
- **칩 클릭은 토글 하나뿐이다.** 거기에 "누가 남겼나 보기"를 얹으면 한 요소에 동작이 둘이 되어,
  목록을 보려다 내 리액션이 달린다.
- `count`와 `users.length`는 항상 같다. 칩은 `count`를 읽는다.
- 삭제된 댓글에도 그대로 붙는다(FR-5.3). 호출부가 판단하지 않는다.

### 본문 렌더 — 허용과 차단

`allowedElements` allowlist에 `unwrapDisallowed`를 건다.
**차단된 태그는 껍데기만 벗기고 글자는 남긴다** — 통째로 지우면 사용자가 친 내용이 소리 없이 사라진다.

| 막는 것            | 이유                               |
| ------------------ | ---------------------------------- |
| `h1`~`h6`          | 300px 패널에서 `2xl` 제목은 과하다 |
| `img`              | 스코프 밖                          |
| `table`            | 가로로 넘친다                      |
| `hr`, `blockquote` | 좁은 폭에서 값이 없다              |

**`strong`과 `em`은 허용하되 아무 스타일도 주지 않는다.** 래퍼조차 남기지 않는다.
좁은 패널에서 굵은 글자가 섞이면 작성자 이름보다 무거워 보여 위계가 뒤집힌다.
태그 자체를 막지 않는 이유는, 막으면 `**` 별표가 그대로 노출되기 때문이다 —
굵은 글자보다 지저분하다.

**raw HTML을 켜지 않는다.** `rehype-raw`가 없으므로 사용자 입력 HTML이 DOM에 들어가지 않고,
따라서 `rehype-sanitize`도 필요 없다. 의존성 둘과 allowlist 관리를 통째로 안 진다.

**`urlTransform`은 두 스킴만 통과시키고 나머지는 기본 동작에 넘긴다.**
기본을 안 거치면 `javascript:` 차단이 풀린다.

```tsx
if (/^(mention|endpoint):\d+$/.test(url)) return url;
return defaultUrlTransform(url);
```

**멘션 칩은 링크 여부가 갈린다.** 팀원 멘션은 갈 곳이 없어 `<span>`이다 —
알림 발송이 목적이라 표시만 한다. 엔드포인트 멘션은 알림 딥링크와 같은 경로로 이동하고,
삭제된 엔드포인트도 그대로 연결한다(상세 화면이 "삭제됨"을 표시한다).

**본문 안에 메서드 뱃지를 쓰지 않는다.** 색 박스가 끼면 문장이 끊긴다.
팀원 멘션과 같은 톤으로 두어 "멘션은 이 모양"이라는 규칙 하나만 남긴다.

**삭제된 댓글은 markdown을 태우지 않는다.** 서버가 마스킹한 평문이라 그대로 표시한다.

**줄바꿈은 `remark-breaks`로 살린다.** markdown 기본은 개행 하나를 무시하는데,
댓글은 문서가 아니라 대화라 사용자가 친 대로 보여야 한다.

### 스레드 접기

**DOM에서 빼지 않고 높이만 줄인다**(`grid-rows-[0fr]` ↔ `[1fr]`).

**답글 작성 중에는 접혀 있어도 강제로 편다.** 안 그러면 에디터가 접힌 영역 안에 열려 안 보인다.

답글 에디터는 답글 버튼 바로 아래, 대댓글 목록 **위**에 열린다.
입력 위치와 결과 위치(맨 아래)는 다르지만, 제출 시 스크롤이 결과로 이동하며
하이라이트가 떠서 어디 달렸는지가 보인다.

### 멘션 팝오버

- **textarea 바로 위에 고정한다.** 커서를 따라가지 않는다 — 캐럿 좌표를 얻으려면
  같은 스타일의 미러 엘리먼트를 만들어 재야 하는데, 패널이 좁아 어차피 뜰 자리가 제한적이다.
- **Base UI `Popover`를 쓰지 않는다.** 열릴 때 포커스를 팝업으로 가져가는데
  여기서는 타이핑을 계속해야 해서 포커스가 textarea에 남아야 한다.
  위치도 트리거 기준이 아니라 입력창 기준이라 `Positioner`가 할 일이 없다.
- **키보드 조작은 textarea의 `onKeyDown`이 처리한다.** 팝오버는 목록을 그리고
  `activeIndex`를 표시할 뿐이다.
- **마우스 선택은 `onMouseDown` + `preventDefault`다.** `onClick`은 blur가 먼저 일어나
  팝오버가 닫힌 뒤 실행된다.
- **검색어가 비면 전체를 준다.** `@`만 쳤을 때 아무것도 안 뜨면 무엇을 칠 수 있는지 모른다.
- 엔드포인트는 path와 summary를 본다(사이드바 검색과 같은 기준, FR-3.4).
  **`method`는 검색 대상이 아니다** — `#GET`을 치면 표시 텍스트와 겹쳐
  사용자가 이미 고른 것을 다시 검색하는 꼴이 된다.
- 후보는 최대 8개. `role="listbox"`를 붙였지만 `aria-activedescendant`는 잇지 않았다.
  combobox 패턴은 구조가 커지고, 키보드로 고르는 동작 자체는 이미 된다.

### AI 요약

- 엔드포인트의 댓글 전체를 요약해 **최상위 댓글 하나**를 만든다. 작성자는 시드된 AI 계정이고
  `isAiGenerated: true`로 온다. 헤더에 "AI 요약" 뱃지가 붙는다.
- **답글은 막고 리액션은 허용한다(FR-13.5).** 요약에 대댓글을 달면 그 대댓글이
  다음 요약의 입력이 되어 자기 참조가 생긴다. 리액션은 그런 문제가 없다.
- 수집 대상에서 **이전 AI 요약 댓글은 제외**된다(백엔드 처리).
- 댓글이 0건이면 400이다. 버튼을 비활성으로 둔다.

### 댓글 이동 `[Owner]`

- **단위는 스레드가 아니라 엔드포인트다.** 그 엔드포인트의 댓글 전량이 한 번에 옮겨간다.
  논의는 엔드포인트에 매인 것이지 개별 스레드에 매인 것이 아니다(FR-12 v0.7).
- 대상 목록에서 삭제된 엔드포인트(FR-12.3)와 **현재 엔드포인트**를 뺀다.
  같은 곳으로 옮기는 것은 무의미하다.
- 검색은 `method path`를 함께 본다. path만 쓰면 `/courses` 계열이 겹쳐 걸러지지 않는다.
  멘션 팝오버와 기준이 반대인데, 여기는 표시 텍스트를 다시 검색하는 상황이 아니다.
- 팝오버에 안내 문구를 둔다. 검색창만 있으면 무엇을 하는 상황인지 알 수 없다.
- 확인 다이얼로그를 거친다(FR-12.5). 이동 후 개수가 0이 되므로
  **문구에 쓸 개수를 미리 담아둔다.**
- 잘못된 `targetEndpointId`는 404가 아니라 **400**이다. 요청 body의 값 문제라
  리소스 은닉 대상이 아니다.

## 배관 5단계 — 실 API 연결

| 순  | 대상                  | 내용                                                        |
| --- | --------------------- | ----------------------------------------------------------- |
| 5-1 | `lib/api/comments.ts` | 8개 함수. 도메인 기준 분할이라 `/endpoints/*` 라우트도 여기 |
| 5-2 | 목록                  | `useQuery(["comments", endpointId])` → `useState` 제거      |
| 5-3 | 작성                  | 최상위, 대댓글. 성공 후 무효화                              |
| 5-4 | 수정, 삭제            | `CommentItem`의 TODO 두 곳                                  |
| 5-5 | 리액션                | 토글. 응답이 없으므로 재조회                                |
| 5-6 | AI 요약               | 대기 표시 필요 — 응답이 느리다                              |
| 5-7 | 이동                  | 성공 후 원본과 대상 양쪽 무효화                             |

**`resolveMentions`가 사라진다.** 목에서는 멘션 id를 이름과 경로로 되살리려고
프론트가 조립했는데, 실제로는 재조회 응답에 `memberMentions`와 `endpointMentions`가
채워져 온다.

**제출 시 `toStorage` → `extractIds` 순서를 지킨다.** 표시 텍스트를 저장 형식으로 바꾼 뒤에
id를 뽑아야 한다. 순서가 뒤집히면 아직 토큰이 아니라 아무것도 안 잡힌다.

**이동 후 무효화 대상이 둘이다.** 원본의 `["comments", fromId]`와 대상의 `["comments", toId]`.
대상 쪽을 빼먹으면 옮겨간 곳을 열었을 때 옛 목록이 보인다.

**AI 요약은 `isPending` 동안 버튼을 비활성으로 두고 표시를 준다.** Azure 호출이 끼어
다른 mutation보다 눈에 띄게 느리다. 아무 반응이 없으면 사용자가 다시 누른다.

**목 데이터를 지운다.** 배관 5가 끝나면 `lib/mock.ts`의 소비처가 없어진다.

### 배관 5 이전의 과도기 증상

배관 4까지 끝난 지금, 댓글 패널만 목이라 아래가 어긋나 보인다. **버그가 아니다.**

- 목 댓글의 `author.id`와 실제 `me.id`가 달라 수정/삭제 버튼이 안 뜬다.
- 목 댓글의 `memberMentions`가 실제 멤버 id와 무관해 멘션 칩이 평문 토큰으로 떨어진다.

둘 다 5-2에서 함께 사라진다.
